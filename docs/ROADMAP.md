## §0. Резюме

**Respo** — десктопное приложение (Windows → позже macOS) для адаптивной веб-разработки:
одна страница в N девайс-вьюпортах одновременно, с синхронизацией взаимодействий,
DevTools на девайс, честной CDP-эмуляцией и инструментами дизайнера. Улучшенный клон
Responsively App, написанный с нуля (их AGPL-код не используется). Полный паритет
функционала — одной большой фазой по утверждённой спеке; перед реализацией — выбор
дизайн-системы по сгенерированным концептам и спайк главного риска (R1, WebContentsView).

Стек и правила — [`../CLAUDE.md`](../CLAUDE.md). Карта документации — [`README.md`](README.md).

## §2. Архитектурные принципы

1. **Производительность — инвариант:** rAF-коалесинг вместо пер-событийных IPC, батчи событий, очередь скриншотов, виртуализация вьюшек. Источники лагов референса не воспроизводить.
2. **CDP-first:** всё «браузерное» (эмуляция, скриншоты, инспект, ввод) — через один debugger-аттач на view; никаких инжектируемых клиент-скриптов и локальных серверов.
3. **OSS-first:** готовые проверенные блоки (MIT/Apache/BSD/ISC); свой код — только для ядра (ViewManager, SyncEngine, оркестрация раскладок). GPL/AGPL запрещены.
4. **Безопасность браузера:** sandbox + contextIsolation везде, валидация входных URL, разрешения «спрашивать по умолчанию» (спека §7a).
5. **Типизированные границы:** все IPC-контракты в `src/shared/ipc.ts` (hub-файл координатора).
6. **Doc-as-code:** документация меняется вместе с кодом.

## §11. Журнал решений

### 2026-09-05 — W5 принята; W6 фаза A принята; лимиты — остаток работ координатор делает сам
**Контекст:** исполнитель W5 (Fable) закрыл задачи 1–11, но его сессия обрывалась на ожидании фоновых субагентов; два ревью Opus дали «mergeable after fixes» (C1: синхронная перезапись стора картинок overlay на каждое чтение; I1–I3: гонка подсветки, gen-токены, таймаут `Runtime.evaluate`). Владелец сообщил, что лимиты на исходе: новых агентов не запускать, остаток — руками координатора. Исполнитель W6 (Fable, отдельный worktree) сдал фазу A.
**Решение:** правки по ревью, отчёт W5, мерж `w5-core` → `main`, слияние `main` в `w6-shell` (10 конфликтов — объединение сторон, единый `OverflowMenu`), README-лендинг в стиле популярных OSS (Bruno/Hoppscotch: hero, бейджи, Install командой, emoji-фичи, Compare), установочный `scripts/install.ps1`, публичные файлы репозитория — только на английском (внутренняя `docs/` остаётся на русском), релиз 0.1.0 — тегом через `release.yml`. Описание/топики/Discussions на GitHub выставлены; репозиторий владелец сделал публичным сам.
**Причина:** экономия лимитов при минимальной потере качества: оставшаяся работа — интеграционная и документационная.
**Последствия:** найденная при приёмке регрессия — кнопка Reload в тулбаре не работала с Task 4 (событие клика уезжало payload'ом в `nav:reload`) — исправлена; перф-спек в полном прогоне шумит (в одиночном p99 10–11 мс) — soft-гейт в CI (W6 B5); скриншоты README сняты до W5 (без кнопки Emulate) — пересъёмка в фазе B. Решения исполнителя W6, принятые координатором: `sharp` исключён (LGPL-бинарники libvips), иконки рендерит сам Electron; мобильные вьюшки масштабируются через CDP `scale` (клик-координаты без деления на zoom для mobile); «Clear all» = `Ctrl+Alt+Backspace` (`Ctrl+Alt+Delete` перехватывает Windows).

### 2026-09-05 — Open source (MIT), публичный репозиторий, релизы через GitHub с автообновлением
**Контекст:** владелец объявил проект open source и бесплатным, попросил автообновление через GitHub Releases (проверка раз в день при первом запуске, видимая кнопка «Update» в шапке, установка в один клик, остаётся только перезапустить), сборку и публикацию **0.1.0**, и оформление репозитория уровня продукта (tagline вида «A better Responsively alternative with MCP…», сравнение с платными Polypane/Sizzy/Blisk).
**Решение:** лицензия **MIT**; репозиторий `prodbyEDDY/respo` переключается в **public** непосредственно перед публикацией релиза (после README/LICENSE и скана истории на секреты); дистрибуция — `electron-updater` + GitHub Releases, релизы собирает GitHub Actions по тегу `v*`; W6 перестроен в две фазы: **A «Release 0.1.0»** (иконка, апдейтер с чипом Update, лицензия/README/CHANGELOG, CI/release-workflow, публикация) и **B «Shell»** (меню, хоткеи/палитра, welcome, устойчивость) → 0.1.x; MCP (W7) выходит как 0.2.0, в README 0.1.0 упоминается честно как «coming in 0.2».
**Причина:** автообновление из GitHub Releases требует публичного репозитория (токены в приложение не зашиваем — §7a); MIT — самая простая лицензия, совместимая с политикой зависимостей и не заражающая форки, в отличие от AGPL референса.
**Последствия:** обновлён [план W6](superpowers/plans/2026-09-05-w6-production-shell.md); строка REL-1.0 в §10 заменена на REL-0.1.0 / REL-0.2.0; подпись кода (R4) остаётся отложенной — README предупреждает о SmartScreen.

### 2026-09-05 — Программа «Production Ready»: W5 → W6 → W7 на Fable-исполнителях
**Контекст:** владелец поставил цель довести Respo до production-ready «до мелочей», с оглядкой на лучших платных конкурентов, и добавить локальный MCP для AI-агентов. Проведена разведка (Sonnet 5): конкуренты, MCP-экосистема, честная матрица спека↔код (§5.7/§5.8 и оболочка §5.9 не реализованы; иконка — дефолт Electron; нет README/CI/апдейтера).
**Решение:** три последовательные волны, каждая — одна длинная сессия **Fable 5.1** (явное разрешение владельца; политика моделей: ресёрч — Sonnet 5, исполнение — Fable, механика — Haiku/Sonnet-субагенты, ревью — Opus 5). W5 «Production Core» — всё на стороне страницы/CDP + must-have-гэпы конкурентов (media/vision/network/geo/locale-эмуляция, Client Hints, каталог 90+, диагностика ошибок/overflow, линейки, overlay, live-reload). W6 «Production Shell» — оболочка, обновления, хоткеи/палитра, инсталлятор, CI. W7 «MCP» — сервер + Connect-экран. Старый план W5 (два параллельных Opus-worktree) отменён — работа по нему не начиналась; пустые ветки `w5a`/`w5b` и worktree удалены.
**Причина:** один сильный исполнитель на волну убирает межагентные конфликты в `ipc.ts`/`TopBar` и держит цельность UX; последовательность W5→W6 даёт W6 полный список хоткеев/фич для справки и палитры; MCP последним — опирается на диагностику и эмуляцию W5.
**Последствия:** планы в `superpowers/plans/2026-09-05-w5|w6|w7-*.md`, диспетч `prompts/_DISPATCH-2026-09-05-W5-W7.md`, research в `docs/research/`; спеку по итогам W5 привести к факту (popups, хоткеи, каталог); LICENSE и подпись кода — открытые решения владельца (REL-1.0).

**Контекст:** старт проекта; референс Responsively App (Electron + `<webview>`, AGPL-3.0) сильно лагает.
**Решение:** писать с нуля на современном Electron (WebContentsView + CDP), Tauri отклонён; код и данные референса не использовать (AGPL), лицензии зависимостей — только MIT/Apache/BSD/ISC.
**Причина:** лаги референса — архитектурные (`<webview>`, нетроттленный IPC, browser-sync-сокеты); Tauri ломает DevTools/CDP-функционал и будущий macOS; AGPL заражает кодовую базу.
**Последствия:** архитектура зафиксирована в спеке §4; правила лицензий — в CLAUDE.md.

### 2026-09-05 — UI polish и релиз 0.1.1
**Контекст:** владелец запросил профессиональную полировку интерфейса, новые иконки/скриншоты, актуальный README и скачиваемый релиз. Lead-команда прочитана для контекста; работа выполнена в `codex/ui-polish-0.1.1` и слита через PR #1.
**Решение:** общий нативный слой с временными снимками под всплывающим UI, исправление typography merge, scrollbar gutter, компактные шапки, единые размеры иконок, ограничение панелей размером окна. Владелец выбрал монограмму R из трёх направлений; все форматы пересобраны из SVG. Impeccable удалён по прямой просьбе владельца и больше не используется.
**Причина:** CSS z-index не перекрывает WebContentsView; custom text-size классы терялись в tailwind-merge. Исправления общих механизмов устраняют проблемы во всех использующих их компонентах.
**Последствия:** [описание реализации и проверок](modules/ui-surfaces.md); новые реальные Windows-compositor скриншоты, demo и генераторы. 0.1.1 — UI polish, не завершение остальных задач W6-B; native menu, deep links, command palette и MCP остаются запланированными. Релиз опубликован после всех проверок; [итоговый отчёт](progress/UI-polish-0.1.1-2026-09-05.md).
