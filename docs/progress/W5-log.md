## Task 2 — UA Client Hints ✅

- **Сделано:** `shared/client-hints.ts` — `clientHintsOf(spec)` выводит platform / platformVersion / architecture / bitness / model / mobile / brand из UA-строки (Android: версия и модель из скобок, `Build/…` отрезается, arch/bitness пустые как у настоящего Chrome on Android; Windows/macOS: замороженные UA не несут реальную версию ОС — hint отдаёт `15.0.0`; CrOS/Linux; Edge → бренд «Microsoft Edge»); `userAgentMetadataFor(hints, engineVersion)` — brands + fullVersionList (Chromium, бренд, GREASE «Not_A Brand»). `CDPController` получил опцию `chromiumVersion` (по умолчанию `process.versions.chrome`) и шлёт `userAgentMetadata` в том же `Network.setUserAgentOverride`.
- **Решения (отклонения от буквы плана):** (1) метаданные **выводятся из UA-строки**, а не хранятся полями `DeviceSpec` — иначе каталог и кастомные девайсы (у которых редактируется только UA) должны были бы быть правыми дважды; «дефолты по типу» получаются через дефолтный UA типа. (2) Major-версия брендов берётся из UA-строки (`Chrome/139`), а `process.versions.chrome` используется для full version только при совпадении major: страница, сравнивающая `Sec-CH-UA-Full-Version-List` с `navigator.userAgent`, должна видеть один браузер. Каталожный `CHROME` будет поднят до 152 в Task 3. (3) Safari/Firefox/CriOS-UA — **без** metadata: Chromium тогда не отдаёт `navigator.userAgentData` вовсе (проверено e2e: iPhone/iPad → `uaData === null`), что и есть честное поведение Safari.
- **Цифры:** +16 юнитов `client-hints.test.ts`, +3 в cdp-controller; e2e `emulation.spec.ts` расширен (Pixel → Android/15.0.0/«Pixel 8»/mobile, Windows/macOS десктопы, Safari-девайсы без hints) 1/1.

## Task 9 — Live-reload для file:// ✅

- **Сделано:** зависимость `chokidar@4.0.3` (MIT; единственная зависимость `readdirp` — MIT), грузится лениво (`await import`). `main/file-watcher.ts` (FileWatcher): `follow(url)` на каждом батче load-state (URL лидера из `LeadTracker`) — `file://*.html` → chokidar на папке страницы, `depth: 3`, `ignoreInitial`, ignore `node_modules`/`.git`; фильтр по расширениям `.html/.htm/.css/.js/.mjs`; debounce 100 мс с коалесингом залпа; **только css** в залпе → одноразовый `Runtime.evaluate` в каждой вьюшке: `<link rel=stylesheet>` с тем же `file:`-pathname получает `?respo-reload=<ts>` (пути — из вотчера, вставляются как JSON, ничего от страницы), если в какой-то вьюшке подменять нечего (`@import`) — reload всех; иначе → `viewManager.reload()`. Уход с `file://` → `close()`, состояние `off`. `watcher:toggle` (пауза = вотчер жив, события отбрасываются) / `watcher:get`; событие `watcher` в `MainEvent` только при смене состояния/после reload (не на каждое файловое событие). Renderer: `stores/watcher.ts`, индикатор `WatcherIndicator` в адресной строке (пульсирующая точка mint при watching — `motion-safe:animate-pulse`, серая при паузе, скрыт при off; tooltip «Live reload: <file> — click to pause»; клик — toggle).
- **Проверено e2e** (`live-reload.spec.ts`, папка во временном каталоге, файлы пишутся тестом): точка видна и `watcher:get.file` = путь страницы; правка css → цвет меняется на всех 5 **без перезагрузки** (маркер `window.__respoMarker` на месте); правка html → reload всех (новый title, маркер пропал); пауза → правка игнорируется 1.2 с, возобновление → применяется; `nav:navigate` на http → точка исчезла, состояние `off`.
- **Решение:** css-hot-swap по подмене `href` (а не `CSS.setStyleSheetText` из спеки §4.2): не требует `CSS.enable`/`DOM.enable` и stylesheetId, работает через один evaluate; спека будет приведена к факту.
- **Цифры:** юниты +14 (`file-watcher.test.ts`); e2e +1.
