# Debug ▸ Outline all elements (`src/main/debug-css.ts`)

**Назначение.** Самый старый приём для «где тут вообще границы блоков» — рамка
вокруг каждого элемента на каждом девайсе разом, одним тумблером (спека
§5.7). Модуль сознательно маленький: один булев переключатель, один
CSS-слой на вьюшку, никакого состояния, которое пережило бы закрытие
приложения — канвас, открывшийся завтра целиком в оранжевых рамках, был бы
загадкой, а не настройкой.

## Как работает

- `DebugCssManager` хранит один флаг `outline` и по записи `{ deviceId, css,
  key, chain }` на зарегистрированную вьюшку — тот же реестр-паттерн, что у
  `GuidesManager`/`DesignOverlayManager` (`registerDevice`/`refresh`/
  `unregisterDevice`), но без `CdpTarget`: слою нечего измерять, значит и
  `Runtime.evaluate` не нужен, а стилю — только `webContents.insertCSS`.
- `setOutline(on)` идемпотентен (выход сразу, если значение не изменилось) и
  применяет/снимает слой сразу на всех зарегистрированных вьюшках.
- `OUTLINE_CSS = '* { outline: 1px solid rgba(255, 62, 0, 0.6) !important; }'`
  — ember-оранжевый акцент дизайн-системы (тот же тон, что у предупреждений),
  одно правило на весь документ.
- Девайс, добавленный в канвас **при включённом** тумблере, получает слой
  сразу при `registerDevice` — тумблер не хранит списка исключений, он либо
  применяется ко всем, либо ни к кому.
- `refresh(deviceId)` (на `did-finish-load` из `view-backend.ts`) сбрасывает
  `key = null` — старый слой умер вместе с документом — и, если тумблер ещё
  включён, вставляет его заново в новый документ.
- Вставка/снятие сериализованы через `chain: Promise<void>` на запись — тот
  же приём, что у направляющих и оверлея: быстрый двойной клик по тумблеру
  не оставляет двух слоёв и не гонится сам с собой.
- Рендерер не хранит ничего, кроме зеркала главного состояния: чекбокс
  **⋯ → Debug ▸ Outline all elements** (`TopBar.tsx: DebugItems`, рядом с
  «Rulers on all devices» — общий саб-меню «Debug», без новых элементов в
  баре) вызывает `stores/debug.ts: setOutline`, которое сразу оптимистично
  проставляет локальный флаг и шлёт `debug:set-outline`; `debug:get`
  спрашивается один раз при старте рендерера (`hydrateDebug`), чтобы
  чекбокс после перезагрузки **окна** совпадал с тем, что реально на
  страницах (сам тумблер, в отличие от документа, приложение не помнит).

## IPC

| Канал | Args | Result | Валидатор (`main/validate.ts`) | Кто вызывает |
|---|---|---|---|---|
| `debug:set-outline` | `[boolean]` | `void` | `validateBoolean` | `stores/debug.ts` `setOutline` (чекбокс `Debug ▸ Outline all elements` в `TopBar.tsx`) |
| `debug:get` | `[]` | `{ outline: boolean }` | — (без аргументов) | `stores/debug.ts` `hydrateDebug`, при старте рендерера |

Отдельного `MainEvent` у модуля нет: тумблер меняется только из самого
рендерера (`debug:set-outline`), обратного канала — «main решил включить сам»
— не существует.

## CDP

`webContents.insertCSS`/`removeInsertedCSS` (через общий `CssLayer` из
`view-backend.ts`) — весь модуль. Ни `Runtime.evaluate`, ни какой-либо другой
CDP-домен не используется: слою нечего мерить и не на что реагировать, кроме
самого тумблера и навигации.

## Персистентность

Нет. `outline` — чисто session-состояние main (не в `PersistedState`,
никакого слайса). Причина — в самом назначении: это диагностический режим
просмотра «прямо сейчас», а не предпочтение вида канвы; сохранённый тумблер
означал бы, что после перезапуска приложения все страницы внезапно в
рамках без видимой причины. `debug:get` при старте рендерера нужен именно
потому, что состояние не пишется — окно могло быть перезагружено (`F5`
рендерера), а main всё ещё жив со своим `outline`.

## Грабли

- Тумблер — глобальный, без списка «этот девайс — не этот»: включение
  проходит по всем зарегистрированным вьюшкам разом, а не по одной.
- Слой снимается **без следа** (`removeInsertedCSS` по сохранённому ключу) —
  выключение не оставляет пустого правила `outline: none`, которое могло бы
  конфликтовать с собственным `outline` страницы.
- Тот же `pending`/`chain`-паттерн, что у направляющих и оверлея, здесь не
  нужен для `pending`: тумблер — не адресованная по девайсу настройка, а
  общий флаг, поэтому регистрация нового устройства просто смотрит на
  текущее значение `this.outline`, а не на карту отложенных вызовов.

## Тесты

Юниты: `main/__tests__/debug-css.test.ts` (`DebugCssManager`: `setOutline`
идемпотентность, применение к уже зарегистрированным и к вновь
зарегистрированному под включённым тумблером, `refresh` на новый документ,
против фейкового `CssLayer`), `stores/__tests__/debug.test.ts`. E2e:
`debug.spec.ts` — 5 вьюшек стартуют с `outlineStyle: none`, тумблер даёт
`solid` на всех пяти, Reload сохраняет `solid` (реинжект на `did-finish-
load`), повторный тумблер возвращает `none` на всех пяти.
