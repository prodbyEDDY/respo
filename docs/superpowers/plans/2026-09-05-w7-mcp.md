# W7 «MCP — Respo для AI-агентов» — план реализации

> **Исполнитель:** один агент Fable 5.1 (третья сессия), ветка `w7-mcp` от `main` после приёмки W6.
> Режим — как в W5/W6. **Черновик:** уточняется координатором после W6 (сверка версий SDK и
> форматов клиентов на дату старта — они меняются быстро).

**Goal:** локальный MCP-сервер внутри Respo, чтобы Claude Code / Codex / Cursor / Windsurf / VS Code /
Claude Desktop / Cline / Zed / Gemini CLI / JetBrains / Kiro / OpenCode / Antigravity / Trae / Continue
могли открыть URL в Respo, выбрать устройства, снять скриншоты по устройствам, измерить элементы, найти
горизонтальный overflow, прочитать консоль и a11y-структуру — лучший из возможных способ проверить сайт
на разных размерах экрана. Плюс экран «Connect your agent» с логотипами клиентов и установкой в один клик.

**Источники:** [research/2026-09-05-mcp-ecosystem.md](../../research/2026-09-05-mcp-ecosystem.md) (протокол, клиенты, логотипы, prior art) ·
спека §4.2, §7a · модули W5 (`diagnostics`, `emulation`, `screenshot-queue`, `cdp-controller`).

## Архитектурные решения (зафиксированы координатором)

1. **Транспорт:** Streamable HTTP на `127.0.0.1`, дефолтный порт `47317` (fallback — эфемерный; фактический порт хранится в `userData/mcp/auth.json` вместе с токеном). SDK — `@modelcontextprotocol/sdk` **v1.x (MIT)** + `zod`; транспортный слой изолировать в один модуль ради будущей миграции на SDK v2/спеку 2026-07-28.
2. **Безопасность:** bearer-токен (32 байта hex, генерируется при первом запуске, «Regenerate» в UI), `enableDnsRebindingProtection: true` + `allowedHosts: ['127.0.0.1', 'localhost']` + проверка `Origin`, bind только loopback, все URL из тулов — через ту же валидацию, что deep-link (http/https/file). `respo_evaluate` — только при явном opt-in в Settings (по умолчанию выключен). Ограничение параллелизма скриншотов — существующая очередь.
3. **stdio-мост** для клиентов без HTTP (Claude Desktop raw-JSON, Zed, Trae): `Respo.exe --mcp-stdio` — приложение в режиме моста: без окна, без single-instance-lock, проксирует stdio ↔ HTTP к работающему Respo (реализация — SDK `StdioServerTransport` ↔ `StreamableHTTPClientTransport`, ~100 строк), при закрытом Respo — понятная ошибка в stderr и tool-error «Respo is not running — launch the app». npm-шим `respo-mcp` — follow-up после публикации.
4. **Сервер живёт с приложением** — никаких фоновых сервисов/трея; статус виден в Settings → Agents.
5. **Логотипы:** SVG из `@lobehub/icons-static-svg` (MIT) и Simple Icons (CC0) копируются в `src/renderer/src/assets/logos/` (только нужные файлы, с `NOTICE.md`-атрибуцией и строкой «Logos belong to their owners, used for identification only»); отсутствующие — монограмма в цветном круге.

## Задачи

### Task 1: Ядро сервера
**Files:** `src/main/mcp/server.ts` (McpServer, регистрация тулов, lifecycle start/stop, порт/токен), `src/main/mcp/auth.ts` (auth.json, генерация/ротация токена, bearer-middleware, Origin), `src/main/mcp/transport-http.ts`, `src/main/mcp/bridge-stdio.ts` (режим `--mcp-stdio`), `src/shared/ipc.ts` (`mcp:status`, `mcp:setEnabled`, `mcp:regenerateToken`, `mcp:setEvaluateAllowed`, событие `mcp` в `MainEvent`: статус + последние вызовы), persistence-слайс `mcp` (enabled, port, evaluateAllowed; токен — в отдельном файле).
**DoD:** юниты (auth, валидация, регистрация), интеграционный тест: SDK-клиент подключается по HTTP с токеном, без токена — 401, с чужим Origin — 403.

### Task 2: Тулы (все с `title`, описаниями для модели, zod-схемами, аннотациями)
| Тул | Аргументы | Возврат | Аннотации |
|---|---|---|---|
| `respo_status` | — | версия, активный сьют, устройства, текущий URL, состояние загрузки | readOnly |
| `respo_open` | `url`, `waitForLoad?` | итог загрузки по устройствам (state/код ошибки) | — |
| `respo_list_devices` | `query?` | каталог + кастомные: id, name, type, W×H, dpr, active | readOnly |
| `respo_set_devices` | `deviceIds[]` \| `suite` | активный набор | — |
| `respo_viewport_sizes` | — | CSS/physical px по активным устройствам | readOnly |
| `respo_screenshot` | `device: id\|'all'`, `fullPage?`, `format?`, `scale?: 1\|'device'`, `maxWidth?` | image-блоки (для `all` при > 3 устройств — файлы в папке скриншотов + `resource_link`, чтобы не раздувать контекст) | readOnly |
| `respo_snapshot` | `device`, `selector?`, `maxNodes?` | компактное a11y-дерево текстом (по образцу Playwright MCP) через `Accessibility.getFullAXTree` | readOnly |
| `respo_measure` | `selector`, `device?` | box model (content/padding/border/margin) + ключевые computed styles на каждом устройстве — «одинаково ли это на 320 и 1440» | readOnly |
| `respo_overflow_check` | `device?` | из W5 diagnostics: есть ли горизонтальный overflow, виновники (селектор, ширина, right) | readOnly |
| `respo_console` | `device?`, `level?`, `since?` | агрегированные консоль-сообщения/исключения | readOnly |
| `respo_breakpoints` | — | найденные `@media` ширины у лидера + подсказка «какие устройства их покрывают» | readOnly |
| `respo_a11y_check` | `device?` | практичные responsive-проверки: viewport meta, tap-targets < 44 px, текст < 12 px, изображения без alt, элементы вне вьюпорта, контраст (если дёшево через AXTree) | readOnly |
| `respo_emulate` | профиль W5 (color scheme, reduced motion, network, geo, locale, vision) | применённый профиль | — |
| `respo_scroll` | `device?`, `y \| selector` | позиция | — |
| `respo_click` / `respo_type` | `selector`, `text?`, `device?` (по умолчанию лидер, зеркалируется SyncEngine) | итог | — |
| `respo_evaluate` | `script`, `device?` | результат (только при opt-in) | openWorld, не readOnly |
**Правила ответов:** текст короткий и структурированный (`structuredContent` + текстовый дубль), изображения — PNG, по умолчанию `scale: 1` и `maxWidth: 1200`; ошибки — `isError: true` с подсказкой, что сделать (например, «no page open — call respo_open»).
**DoD:** юниты на каждый тул с фейковыми менеджерами; e2e `mcp.spec.ts`: приложение запущено, SDK-клиент вызывает `respo_open` → `respo_screenshot('all')` → `respo_overflow_check` на фикстуре с overflow — получает виновника.

### Task 3: Settings → Agents («Connect your agent»)
**Files:** `components/settings/AgentsPanel.tsx`, `lib/mcp-clients.ts` (таблица клиентов: имя, логотип, поддержка HTTP/stdio, путь конфига Win/mac, генератор сниппета JSON/TOML/YAML, CLI-однострочник, deeplink), `assets/logos/*.svg`.
**UX:** статус-строка (Running on 127.0.0.1:47317 · N calls today · last: respo_screenshot 2 min ago), тумблер Enable, кнопка Regenerate token (с подтверждением), тумблер Allow `respo_evaluate` (с предупреждением). Сетка логотипов; клик по клиенту → карточка: 1) кнопка **Install** (deeplink для Cursor/VS Code; для Claude Code/Codex/VS Code — CLI-команда с кнопкой Copy; для остальных — сниппет), 2) сниппет с живыми port+token и кнопкой Copy, 3) «Open config file» / «Reveal folder» по пути для текущей ОС (создаёт файл с пустым `mcpServers`, если нет — с подтверждением), 4) короткая подсказка «Restart the client after adding». Лог последних 50 вызовов (тул, устройство, длительность) — свёрнутый блок.
**DoD:** сниппеты для всех клиентов из research-таблицы проходят снапшот-тесты; deeplink Cursor/VS Code открываются (ручная проверка); UI в обеих темах.

### Task 4: Документация и релиз
