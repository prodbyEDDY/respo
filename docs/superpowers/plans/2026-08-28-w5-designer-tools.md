# W5 «Designer Tools + Live Reload» Implementation Plan

> Режим: ДВА ПАРАЛЛЕЛЬНЫХ Opus-агента в отдельных git worktree (зоны не пересекаются, кроме аддитивных правок `src/shared/ipc.ts`/`persistence-types.ts` — конфликты мержит координатор). Полные прогоны — разрешены (по разу на задачу). Финальное ревью ветки + фикс-волна.

**Goal:** Линейки/направляющие, Design Overlay, симуляция зрения, live-reload локальных файлов.

**Spec:** §5.7–5.8, §4.2 (FileWatcher). Constraints и UX-приоритет — как в прежних волнах.

## Агент A — зона: renderer previewer/overlay (+свои слайсы persistence)

### Task A1: Линейки и направляющие
Пер-девайс тумблер (иконка в шапке, hotkey alt+r для лид-девайса): горизонтальная+вертикальная линейки (30px, деления по CSS-px девайса с учётом зума), синхронизированные со скроллом страницы (позиция скролла уже приходит в sync-данных — переиспользовать канал, НЕ создавать новый поток). Направляющие: drag с линейки на страницу, drag обратно — удалить; persist по разрешению `WxH` (аддитивный слайс). Отрисовка — renderer поверх рамки (позиции считаются от рамки; помнить: нативная вьюшка композитится выше DOM — линейки размещать ВНЕ прямоугольника вьюшки: рамка расширяется на 30px при включении, вьюшка не перекрывает линейки). Без библиотек, если геометрия простая; @scena/react-guides (MIT) — если быстрее.

### Task A2: Design Overlay
Кнопка в шапке девайса → Dialog: загрузить изображение макета (диалог в main → data URL, кап 10MB), opacity-слайдер, режимы Overlay/Side-by-side, enable/disable, remove; persist по разрешению (изображение — в отдельном ключе persistence, не раздувать основной state; лимит суммарно 100MB c LRU). ВАЖНО: нативная вьюшка выше DOM — оверлей поверх страницы невозможен DOM'ом. Решение: overlay-режим рендерит изображение в САМОЙ странице через CDP (добавить `<img>`-слой через Runtime.evaluate в isolated world ИЛИ через `Page.addCompositorTab...` — нет; практично: CSS background на html::before через CDP insertCSS в isolated world) — выбрать, доказать скриншотом, задокументировать; шторка-слайдер и панорамирование в такт скроллу — через параметры этого слоя. Side-by-side — чисто renderer (изображение рядом с рамкой). Если CDP-путь окажется хрупким — честно доложить и оставить side-by-side + запись в отчёт.

## Агент B — зона: main (cdp/vision/file-watcher) + мелкий UI-дропдаун

### Task B1: Симуляция зрения
CDP-first: `Emulation.setEmulatedVisionDeficiency` (achromatopsia, deuteranopia, protanopia, tritanopia, blurredVision, reducedContrast — проверить поддержку в текущем Chromium). Дропдаун (иконка глаза в шапке девайса + глобальный в kebab: применить ко всем). Состояние в сторе, повтор после навигации (CDP-настройка переживает навигацию? проверить; если нет — реаппликация по did-navigate). Расширенные симуляции (глаукома/катаракта) — ТОЛЬКО если CDP не покрывает и решение чистое; иначе скоуп ограничивается CDP-набором (задокументировать).

### Task B2: Live-reload локальных файлов
Когда лид-URL — `file://*.html`: chokidar (уже в транзитивах? если нет — npm i chokidar, MIT) следит за файлом + соседними `**/*.css`/`**/*.js` (глубина разумная, ignore node_modules); изменение css → hot-inject во все вьюшки через CDP (`CSS.enable`+`setStyleSheetText` сложно — практичнее: `Runtime.evaluate` перезагрузка `<link>` с cache-bust в isolated world; выбрать и задокументировать), прочее → reload всех. Индикатор «watching» у адресной строки (глазик/пульс, ненавязчиво). Остановка вотчера при уходе с file://. Никаких вотчеров для http(s).
